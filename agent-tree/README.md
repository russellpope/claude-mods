# agent-tree

A pane for herdr and Rex users: the agents this Claude session spawned, the agents those spawned, and so on, each with status, model, context, estimated cost and ticket. `/agent-tree` toggles it.

- **Tree view**: rooted at this session's herdr pane. `●` working, `◌` idle, `!` blocked (herdr status or a `BLOCKED:` title), `✓` done (a `DONE:` title; herdr's own `done` only means a turn ended, shown as idle), `✗` pane gone (last numbers kept). Click a name to focus that pane; on the terminal the whole name cell, at least 12 columns wide, takes the click, here and in the other lists.
- **All view**: every agent herdr lists (in a Rex session, every agent Rex and herdr list), grouped by repo; worktrees fold into their repo.
- **Batch bar**: when a worker's cwd is a ticket's `workspace:`, the header shows that ticket's batch: fixed / in-progress of total.
- **Batch ETA**: tickets carry no times, so the mod notes when the batch's fixed count rises. After two such closes the batch line ends with an estimate, `~1h 20m left`: the tickets not yet fixed times the mean time per close since the mod first saw the batch. The estimate holds for one mean interval after a close, then grows while nothing closes. Closes from before that are not counted. A count that drops (a ticket reopened) records nothing, nor does climbing back to the highest count seen. The records survive a reload, one per batch stamp for the last five batches, so a tree that moves between two batches keeps both.
- **Errored rows**: a Claude worker whose turn ended on an API error (model `<synthetic>`) and that its multiplexer does not report working shows `⚠` and the reason as its note, `API error: server_error (529)`. The status line counts it after the blocked count (`tree 2● 1! 1⚠`), and the crab sweats. The row stays in the tree, whatever its title says, until the agent goes on: a prompt or an answer clears it. A local command (`/model`, `! pwd`), a meta line or a `<synthetic>` line Claude Code writes itself does not. Its `continue` button sends the agent one prompt, the `continuePrompt` setting (default `Continue your dispatch from where you stopped.`): `herdr agent prompt`, or `rex send` and Enter. The mod refreshes first and sends only to the agent the row showed, still errored and not working. One press sends at most once: a second press while it runs, or before the transcript moves on, is refused. On Rex a fresh pane can drop the Enter, so the mod looks a second later and, if the agent is not working, presses Enter once more; if that is lost too, a toast says the text may be waiting in its composer. A toast says what happened each time. Nothing is sent without a press: an auth error needs a login first. Agents on another Rex host are never errored, since their transcripts are on that machine. The error line no longer replaces the row's model and context. Codex workers are not covered: their rollouts are not read for errors.
- **Model changes**: when a worker's model or effort changes, the model cell gets a `*` and the note says what it was, `was Opus 5.5·high`, for the rest of the row's life. Claude transcripts and codex rollouts both count.
- **Crab**: types while workers work, holds a magnifier when only reviewers do, sweats when something is blocked, sleeps when all is idle, parties when the batch is all fixed. Set `motion` to `off` to keep it still.
- **Tokens**: the header's count adds every call's input, cache reads included, and its output. An agent sends its whole context again on every call, mostly from the prompt cache, so cache reads are nearly all of it. The line under the cost says how much, and how much the models wrote: `2.4B tok · 98% cache reads · 6.6M output`.
- **Codex workers**: status comes from herdr, as for every agent. Model, effort, context and tokens come from the session's rollout file, found under any codex home named `~/.codex*` (`~/.codex`, or `~/.codex-alt` for a worker run with `CODEX_HOME=~/.codex-alt`); a worker whose home is named otherwise keeps a blank row. The percent is the one codex's own bar shows. Tokens are the session's own: sub-agents codex spawns, such as its auto-reviewer, are not counted. Codex rows show no cost, since codex bills against a ChatGPT plan, and beside them the header's estimate reads `≈$… Claude only`.
- **Dings**: herdr plays a sound when an agent's turn ends in a background tab (`working` → `done`) or it starts asking for input (`blocked`). This pane keeps dings only for this session's tree, including recorded descendants and adopted workers. The Dings section lists the ones that need you, newest first, each with its age and the pane's title at the time: a descendant asking, a lead whose title reads `DONE:`, or a worker whose lead has stopped. This session's own turns and unrelated sessions are left out, and an agent herdr has no name for shows its tab's label. Each one puts a `!` on its tree row until it is acknowledged: by its `✓` (you stay put), by pressing its name (you go to its pane), by `ack all`, or by the agent working again. Acknowledged, collapsed below, keeps the newest 10, along with the dings that never needed you, dim with the reason: a worker finishing while its lead runs, or a lead ending a turn without `DONE:`. Dings are seen only while this mod is polling: every 2 s with the pane open, every 10 s otherwise in a session that has spawned workers.
- **Status line**: `tree 3● 1!` while the tree has live members, `1⚠` after it for errored rows, then `· 2 need you` while dings wait on you.

## For leads

In a herdr or Rex pane, the mod gives the session a `team_status` tool, always loaded. It answers in plain text: a header with the counts, the dings that need you and the batch with its ETA, then one line per tree node, indented by depth, with name, role, status, ticket, model and effort (and what it was, after a change), context percent, time in the tree, a `DONE:` or `BLOCKED:` title and the pane id. An errored row gives its reason. `scope: "all"` lists every agent, grouped by repo, as the All view does. The tool refreshes first when its data is over 2 s old (after a refresh the multiplexer did not answer, it waits 2 s before asking again, and says how old its state is), reports what it sees, and returns: it never waits for a change and never sends anything to a pane. A lead calls it in place of `herdr pane read` or `sleep`.

## In Rex

The same pane runs in a Rex terminal (`REX_BLOCK` set). When herdr runs inside Rex, herdr wins, since it is the nearer one, and a herdr session never lists Rex.

- **herdr teams**: a Rex session also lists herdr's agents, so a team whose lead and workers run in herdr panes shows under the Rex session that started it. Each poll runs `herdr agent list` beside Rex's list, with the same 5 s limit. If herdr is missing, not running, slow or answers nonsense, the pane shows Rex's agents alone and no error. Each row keeps its multiplexer: pressing a herdr row runs `herdr agent focus <pane>`, and a herdr ding takes its name from `herdr tab list`, a Rex ding from Rex's window labels. herdr can only focus a pane when a herdr client is attached. Without one, a toast gives herdr's reason and the ding stays open.
- **herdr spawns**: a Bash call whose text names `herdr`, a lane launcher (`launch_lane*.py`, `launch_*codex*.py`) or a team helper (`claude-team`, `codex-team`, `rex-team`) makes the mod compare both lists before and after it. A launcher that starts herdr agents itself still counts. Each new herdr agent becomes an edge from this Rex block, carrying its herdr workspace as `session`. When the call starts a whole team, only the agent whose name says `lead` gets an edge: the workers in its workspace are adopted beneath it, as for any lead. A herdr command never records a new Rex block, and a `rex` command never records a herdr agent.

- **Listing**: one `rex do` Lua script, each poll, reads every terminal block in every session on this server and on each host `rex hosts` lists. Status is what the program reports with OSC 7501: Claude Code and codex both report it, so `working`, `idle`, `blocked` and `done` mean what they mean in herdr. A program's `error` reads as blocked. opencode is listed by its process name with no status. A host that does not answer is skipped.
- **Spawns**: a Bash call that runs `rex run`, `rex split`, `rex new` or `rex window new` with claude, codex or opencode in it, or `rex send`s one, records an edge for the new block. The edge carries the child's Rex session and host as well as its block id. The team skills' helper, `rex-team.sh`, counts the same way: its `spawn` and `launch` create a block, and its `prompt` types into one.
- **One edge per spawn**: `rex-team.sh spawn` and `launch` write an edge themselves (`via: "rex-team"`) before the Bash call returns. The mod reads the ledger again before writing its own, and skips a child that already has an edge from the same parent on the same host, written during that call and no more than three minutes old. A worker started again later still gets a new edge.
- **Names and DONE:**: Rex has one label per block. The label set at spawn (`rex run --label demo-impl`) is the agent's name. A worker marks itself finished or stuck by renaming its block: `rex block rename "$REX_BLOCK" "DONE: <outcome>"` (or `BLOCKED:`). The tree keeps the spawn name.
- **Usage**: a Claude session is found from `~/.claude/sessions/<pid>.json`. A codex thread is found from codex's logs (`~/.codex*/logs_*.sqlite`), which keep about a day. So a codex worker that has been idle longer than that shows a blank row until it works again. Agents on another host show status but no usage, because their files are on that machine.
- **Focus**: pressing a Rex row's name focuses the block in its session, then asks the Rex app that owns this session's block to show that session and tab.
- **Spawn detection**: any `rex run`, `split`, `new`, `window new` or `send`, or the helper's `spawn`, `launch` or `prompt` followed by a session (a variable or a `session:` id), makes the mod compare the agent list before and after the call, so a launch from a variable or a script still counts. A block printed by the command but not yet running an agent is recorded only when the command names a harness. `rex send-key` never counts.
- **codex workers**: two things stop a codex worker from using `rex`. First, the codex TUI runs its shell commands through the shared codex app-server daemon, so they get the daemon's environment: no `REX_BLOCK` or `REX_SESSION`, and no `rex` on the PATH. Starting codex with `-c features.daemon_auto_start=false` and choosing "Run without daemon this time" gives the commands the pane's environment. Second, codex's sandbox blocks the Rex socket, so `rex block rename` fails unless the command is approved to run outside it.

## How it knows the tree

Neither herdr nor Rex records which pane spawned which. Every Claude session running this mod writes one small file per agent it starts to `~/.local/state/agent-tree/edges/` (`{"v":1,"parent","parentSession","child","name","via","at"}`, plus `session` and, for a child on another host, `server`). Agents started by a non-Claude lead (codex, opencode, pi) are linked only when the lead starts them with `rex-team.sh spawn` or `launch`, which writes the same file with `via: "rex-team"`; it takes the parent from `REX_TEAM_PARENT`, or from `REX_BLOCK` when that is unset. Any other collector can write the same files with its own `via`. The mod reads such a file like its own, so a lead's edge written by hand still puts its workspace's workers beneath it.

Cost is an estimate from token counts and a price table (`hooks/usage.ts`), not a bill.
